# ADR 0001：新项目独立建设，旧项目仅作迁移来源

- 状态：已接受
- 日期：2026-08-12
- 决策来源：P0 构建方案 §3.1、§14

## 背景

旧项目 `021-EasyPhone_AI` 在多次比赛迭代中积累了归档分支、旧比赛材料、
模拟功能（"演示发送给家人"按钮、模拟成功提示）、过期文档和隐性耦合。
旧系统还曾出现真实模型调用超时并回退到低风险路径（fail-open）的安全语义缺陷。

如果在新版本上继续基于旧仓库的归档分支开发，会继承这些历史包袱，
难以区分"已验证资产"与"应废弃代码"。

## 决策

建立全新的独立项目 `EasyPhoneAI-X`，拥有独立的 Git 历史。
旧项目 `021-EasyPhone_AI` 的 `main` 分支仅作为**已验证资产的迁移来源**，
不从归档分支整体复制。

## 实施约束

- 在新项目中建立独立 Git 历史。
- 以旧项目 `main` 的文件为迁移来源。
- 对每项迁移**重新提交并重新验证**，不保留与新目标无关的历史文件。
- 不迁移旧项目未跟踪文件、本地环境文件、构建产物或密钥。

## 迁移范围（方案 §5）

**迁移并调整**：风险关键词库与 MAX 规则、路由保险丝、白名单教程、
求助卡构建与危险话术过滤、Web Speech 语音能力、领域与解析测试。

**不迁移**：旧 DeepSeek/GMI 客户端与供应商硬编码、旧版 fail-open 安全语义、
"演示发送给家人"按钮与模拟成功提示、旧比赛计划/幻灯片/构建产物、
`.env.local`/Token/API Key。

## 后果

- 新项目从干净基线开始，安全语义（技术故障 vs 安全不确定性）可重新定义。
- 迁移成本：每项资产需要重新理解、调整目录归属、补测试。这是有意识付出的代价。
- 旧项目保持只读，作为对照与资产库，不再接收新功能。
