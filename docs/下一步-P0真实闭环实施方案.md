# EasyPhoneAI-X 下一步实施方案

## 1. 当前判断

项目已经具备可复用的安全核心：确定性风险分类、高风险强中止、白名单教程、求助卡、决策联合类型、Qwen Vision adapter、单元测试和生产构建。

方案执行状态（2026-08-13）：`/assist` 已统一文字、语音和截图入口；截图同意、预览和手动遮挡已实现；Vision 观察事实已接入风险 MAX；退款教程和三条移动端 Chrome E2E 已完成。真实 Qwen、截图触控验收和完整任务状态机仍未完成。

下一阶段把目标限定为：

> 用户通过同一个正式入口提交文字或截图，系统返回一步指导、停止或无法确认；三条比赛路径有浏览器证据，所有材料标明证据等级。

## 2. 完成标准

下一阶段完成后，项目必须满足以下条件：

1. 首页文字、语音和截图使用同一套决策策略，不设置演示专用隐藏分支。
2. 截图上传前显示用途、风险和取消方式；用户可以预览并手动遮挡敏感区域。
3. 未同意时，客户端不提交截图；服务端继续校验 `consentId`。
4. Vision 只输出可观察事实。领域策略根据这些事实升级风险，模型不能降低规则风险。
5. 低风险微信声音路径能完成一步指导。
6. 中风险退款路径只展示审核过的可逆步骤；一旦出现付款、验证码或陌生渠道，系统转入停止页。
7. 高风险转账、验证码或屏幕共享输入直接停止，并生成脱敏求助卡。
8. 模糊截图、非法模型输出、超时和无匹配状态进入 `UNKNOWN`，不显示具体按钮指导。
9. 三条浏览器 E2E、类型检查、单元测试和生产构建通过。
10. README、证据清单、录屏和截图标明 `[本地浏览器]`、`[固定回放]` 或 `[真实模型调用]`。

## 3. 实施策略

### 3.1 截止前：先交付可证明的闭环

仓库内 PRD 记录的初赛截止时间为 2026-08-13 24:00。截止前只做页面接线、固定回放 E2E、关键缺陷修复和证据整理。

截止前不改六层架构，不引入数据库，不建设家属端，不实现自动点击，也不把完整任务状态机作为提交前置条件。

### 3.2 提交后：补真实 Vision 和状态机

真实 Qwen 调用需要 API Key、区域端点和供应商条款确认。该工作单独验收，不能用固定 fixture 代替。

完整任务包、截图状态验证和真实老人测试安排在提交后。每项能力形成独立证据，避免一次改动同时触碰 UI、领域策略和 Provider。

## 4. 阶段一：统一页面入口

### 目标

首页不再只调用 `routeToInput()`。文字、语音和截图都进入一个客户端工作流，由正式决策结果决定显示指导、停止或 `UNKNOWN`。

### 实现范围

- 新增 `src/app/assist/page.tsx` 和对应 Client Component，承载一次完整求助会话。
- 抽出 `src/lib/decision/decision-client.ts`，负责组装 `multipart/form-data`、调用 `POST /api/v2/decision` 和解析错误响应。
- 首页文字与语音提交统一跳到 `/assist`，不在浏览器端自行决定风险页面。
- 将指导、风险停止和 `UNKNOWN` 的展示拆成可复用组件；现有页面保留深链守卫。
- 请求失败时给出重试、改用文字和回首页三个安全出口。

### 不做

- 不保存会话到数据库。
- 不把完整 `GuidanceDecision` 放进 URL。
- 不信任客户端传入的风险等级。

### 验收

- `微信没有声音` 返回 `guide`。
- `对方让我开屏幕共享` 返回 `stop`，页面没有继续操作按钮。
- 空输入不发送请求。
- API 返回错误时页面不白屏，也不自动当作低风险。

### 验证

```powershell
pnpm.cmd test
pnpm.cmd typecheck
pnpm.cmd build
```

## 5. 阶段二：截图同意、预览和手动遮挡

### 目标

用户在浏览器本地处理截图，确认后才把处理后的图片交给服务器。

### 实现范围

- 新增截图选择区，限制为 PNG、JPEG、WebP 和单张 4 MB。
- 用 `canvas` 显示预览，提供矩形涂抹、撤销、重置、重选和取消。
- 上传内容来自遮挡后的 canvas，不上传原始文件。
- 同意区说明处理目的、可能出现的敏感信息、请求结束后不保存原图和取消方式。
- 用户勾选同意后生成本次会话使用的 `consentId`。
- 浏览器端限制只改善体验；服务端继续检查 MIME、大小和 `consentId`。

### 边界

P0 只承诺手动遮挡。自动识别手机号、验证码和银行卡号需要单独的准确率与漏检评测，当前材料不得声称已实现。

### 验收

- 未勾选同意时上传按钮不可用。
- 用户遮挡后，网络请求只包含导出的处理图。
- 取消后清空预览、canvas 和同意状态。
- 超大图片和不支持格式在客户端提示，服务端仍能拒绝绕过客户端的请求。
- 键盘可以完成选择、同意、提交和取消。

### 验证

- 组件测试覆盖同意门禁和状态清理。
- 浏览器网络面板确认请求体不含原始文件对象。
- 375 px 竖屏和 200% 文本缩放下，遮挡、取消和提交按钮可见。

## 6. 阶段三：让 Vision 结果进入安全策略

### 目标

Vision 负责提取页面事实，领域层负责风险升级和任务匹配。

### 实现范围

- 新增 `src/domain/risk/assess-observation-risk.ts`，从 `appId`、`screenState` 和可见元素标签中提取确定性风险命中。
- 在 `decide-next.ts` 中用观察风险替换当前固定的 `vision -> low` 映射。
- 保留 `mergeRiskByMax()` 作为唯一风险合并入口。
- 新增退款任务包，至少包含“订单详情”“申请退款”“退款方式确认”三个审核状态。
- 任务状态不匹配时返回 `clarify` 或 `unsupported`，不根据模型自由文本生成按钮操作。
- 截图中出现付款、验证码、陌生链接、共享屏幕或远程控制时升级为 `high/critical`。

### 安全约束

- 页面文字属于不可信数据，只作为分类输入，不作为指令执行。
- Vision 的按钮名称和位置不能直接触发跳转、点击或外部发送。
- `UNKNOWN`、低置信度和 Schema 错误不能进入 `guide`。
- 高风险规则命中时，即使 Vision 超时，系统仍返回 `stop`。

### 验收

- 规则 `low` + 截图出现“验证码”得到 `critical`。
- 规则 `high` + Vision `low` 仍得到 `high`。
- 退款页面匹配审核状态后，只返回任务包中的下一步。
- 模糊截图、Prompt Injection 文本和未知 App 返回 `UNKNOWN`。
- 每次决策记录策略版本、模型版本、任务包版本和脱敏 trace。

## 7. 阶段四：浏览器验收与证据

### 自动化门禁

引入 Playwright 作为开发依赖，建立以下 E2E：

1. 低风险：输入“微信没有声音”后显示一个步骤和成功信号。
2. 中风险：固定退款截图进入审核步骤；危险退款截图升级到停止页。
3. 高风险：屏幕共享或验证码直接停止并生成求助卡。
4. 故障：Vision 超时或非法输出进入 `UNKNOWN`。
5. 分享失败：`navigator.share` 和 clipboard 都失败时，用户仍可长按复制求助卡。

### 人工验收

- Chrome 移动视口 375 × 812。
- 200% 文本缩放。
- 键盘操作和可见焦点。
- Web Speech 不支持、拒绝权限和识别失败。
- 系统分享可用、不可用和用户取消。

### 证据产物

- `docs/证据清单.md`：逐条记录命令、日期、commit 和证据等级。
- 固定回放录屏：画面持续显示 `[固定回放]`。
- 本地浏览器录屏：画面显示 `[本地浏览器]`。
- 真实 Qwen 日志：仅记录 trace、版本、延迟和决策，不记录原始截图或模型原文。

固定回放使用显式的开发配置选择 `FixtureVisionProvider`。Provider 只替代外部模型 I/O，返回值继续经过 `parseUIObservation`、风险 MAX、任务状态匹配和 Allowed Action 检查。页面始终显示回放标识，生产构建默认关闭该配置。不得根据用户输入绕过正式决策链直接返回预设页面。

## 9. 提交后的实施顺序

1. 完成 canvas 手动遮挡和浏览器无障碍验收。
2. 实现观察风险映射和退款任务包。
3. 使用真实 Key 验证 Qwen 成功、超时、限流和非法输出。
4. 用下一张截图验证步骤状态变化，替换“点好了就算完成”的逻辑。
5. 邀请 3 至 5 名目标用户完成固定任务，记录误触、理解困难、求助次数和失败原因。

真实用户测试前不引入数据库、家属账号或后台。只有测试证明结构化交接需要持久化和回传，才进入 P1 数据设计。

## 10. 风险与处置

| 风险 | 影响 | 处置 |
|---|---|---|
| 首页与 API 同时维护两套路由 | 演示结果不一致 | `/assist` 成为主入口；旧页面只保留深链兼容 |
| canvas 遮挡在移动端难操作 | 用户可能提交敏感区域 | 支持大尺寸矩形、撤销和重选；提交前显示最终预览 |
| Vision 输出合法但事实错误 | 给出错误按钮指导 | 任务包状态匹配和 Allowed Action 再校验；无匹配转 `UNKNOWN` |
| 退款路径内容不足 | 中风险演示无法闭环 | 只补一条已审核退款任务，不扩展到完整电商教程库 |
| 真实模型延迟或限流 | 现场演示不稳定 | 保留明确标注的固定回放；真实失败展示 `UNKNOWN` |
| E2E 为赶时间覆盖过少 | 页面回归无法发现 | 截止前锁三条主路径；提交后补故障和无障碍用例 |

## 11. 暂不实施

- 自动点击、Accessibility Service 和远程控制。
- 数据库、登录、可信联系人和家属收件箱。
- 自动发送微信、短信或邮件。
- 自动敏感信息识别的产品承诺。
- 多模型路由、微服务、向量库和运营后台。
- 未经真实用户验证的大规模教程扩充。

这些能力不会提高当前 P0 的可验证程度，却会增加隐私、权限和演示稳定性风险。
