# EasyPhoneAI-X「安心下一步」P0 构建方案

## 1. 方案摘要

- 在 `EasyPhoneAI-X` 建立独立新项目，不在旧项目的归档分支上继续开发。
- 沿用 Next.js 16、React 19、TypeScript strict、Tailwind CSS 4、Node.js 24 和 pnpm 10，构建模块化单体。
- 从 `021-EasyPhone_AI` 选择性迁移风险分类、路由保险丝、白名单教程、求助卡、语音能力和相关测试；不整体复制旧仓库。
- 第一阶段交付比赛 P0：低风险一步指导、高风险强中止、截图识别失败进入 `UNKNOWN`、用户确认后分享求助卡。
- 截图理解接入百炼 Qwen Vision；固定脱敏截图仅用于回归测试和离线演示，并明确标注证据来源。

## 2. 项目目标与边界

### 2.1 产品定位

保留“爸妈别急 / EasyPhone AI”品牌，以“安心下一步”作为比赛版本能力名：

> 面向银发用户的数字生活安全副驾。系统看懂用户当前所在步骤，只给出安全的下一步；遇到风险或无法确认时停下来，并把必要上下文交给家人。

### 2.2 P0 成功标准

P0 必须通过同一套真实路由和策略完成三条演示路径：

1. 低风险：微信声音或视频通话，一次只给一个可逆步骤和成功信号。
2. 中风险：电商退款，只允许已审核步骤；出现付款、验证码或陌生渠道时立即升级。
3. 高风险：屏幕共享、验证码、转账等场景直接停止，并生成脱敏求助卡。

### 2.3 明确不做

- 不自动点击第三方 App。
- 不使用 Android Accessibility Service 代替用户操作。
- 不远程控制手机。
- 不处理真实支付、OTP 或支付密码。
- 不建设账号、数据库、家属端收件箱和运营后台。
- 不后台静默发送微信或短信。
- 不拆微服务，不引入与 P0 无关的生产依赖。

## 3. 工程基线

### 3.1 新项目策略

`EasyPhoneAI-X` 是新的主线项目，旧项目只作为已验证资产库。这样可以复用成熟能力，同时避免继承归档分支、旧比赛材料、模拟功能、过期文档和隐性耦合。

实施时应：

- 在新项目中建立独立 Git 历史。
- 以旧项目 `main` 的文件为迁移来源，不从当前归档分支整体复制。
- 对每项迁移重新提交并重新验证，不保留与新目标无关的历史文件。
- 不迁移旧项目未跟踪文件、本地环境文件、构建产物或密钥。

### 3.2 技术栈

- Web：Next.js 16 App Router。
- UI：React 19、Server Components 与必要的 Client Components。
- 语言：TypeScript strict，外部数据从 `unknown` 开始收敛。
- 样式：Tailwind CSS 4 与集中式 CSS design tokens。
- 测试：Node.js Test Runner；浏览器 E2E 使用 Playwright。
- 包管理：pnpm 10，锁定 lockfile。
- 运行时：Node.js 24。
- 部署：保持 Node.js 兼容的单体部署，不将领域逻辑绑定到特定平台 SDK。

## 4. 目标架构

### 4.1 目录与职责

```text
src/
  app/                         # Next.js 页面与 Route Handlers
  components/                  # 无业务决策的适老化 UI
  domain/
    risk/                      # 风险等级、规则、MAX 不变量
    guidance/                  # 任务状态机、允许动作、指导步骤
    handoff/                   # 求助卡与家庭交接规则
  application/
    decide-next.ts             # 合并输入、风险、观察与任务状态
    observe-screen.ts          # 截图观察用例
    guide-next-step.ts         # 下一步指导用例
    build-handoff.ts           # 求助卡用例
    ports/                     # Provider、Telemetry 等接口
  contracts/                   # API DTO、Schema、错误码
  infrastructure/
    ai/qwen-vision-adapter.ts  # 百炼 Qwen Vision 实现
    telemetry/                 # 脱敏结构化事件
  lib/                         # 无业务含义的通用工具
content/
  task-packs/                  # 已审核、版本化的任务状态包
tests/
  fixtures/                    # 脱敏视觉与策略评测样例
docs/
  adr/                         # 跨模块与安全决策记录
```

### 4.2 依赖方向

- `app/components` 可以依赖 `application` 和 `contracts`，不得直接拼接模型请求或定义风险策略。
- `application` 编排用例，只依赖 `domain` 与 ports。
- `domain` 只包含类型、纯函数、策略和状态机，不导入 React、Next.js、`fetch`、数据库或环境变量。
- `infrastructure` 实现 Provider 与 Telemetry，不得反向定义业务规则。
- `contracts` 管理跨边界协议；任何外部输入和模型输出必须先通过运行时校验。

## 5. 旧项目迁移范围

### 5.1 迁移并调整

- 风险关键词库、输入归一化、多个命中取最高风险的规则。
- 高风险绕过确认和教程页面的路由保险丝。
- 白名单教程数据和“一次一步”的指导交互。
- 求助卡构建、危险话术过滤和纯文本序列化。
- Web Speech API、SpeechSynthesis 和文字输入兜底。
- 领域测试、AI 输出解析测试、无障碍对比度测试。

### 5.2 不直接迁移

- 旧 DeepSeek/GMI 客户端和供应商硬编码。
- 旧版 `fail-open` 的安全语义。
- “演示发送给家人”按钮和模拟成功提示。
- 旧比赛计划、幻灯片、OpenPRD 状态、构建产物与临时证据图。
- `.env.local`、Token、API Key 或任何本地配置值。

旧系统曾出现真实模型调用超时并回退到低风险路径。新系统必须将“技术故障回退”和“安全不确定性”分开：技术故障可以继续使用确定性规则或模板，安全不确定性必须进入 `UNKNOWN` 或 `STOP`。

## 6. 核心领域模型与决策链

### 6.1 公开联合类型

```ts
export type GuidanceDecision =
  | {
      kind: 'guide'
      risk: 'low' | 'medium'
      step: GuidanceStep
    }
  | {
      kind: 'stop'
      risk: 'high' | 'critical'
      handoff: HandoffCard
    }
  | {
      kind: 'clarify'
      risk: 'unknown'
      questions: readonly string[]
    }
  | {
      kind: 'unsupported'
      reasonCode: string
    }
```

调用方必须穷尽处理所有状态，禁止把 `unknown` 当作 `low`。

### 6.2 决策顺序

```text
输入校验
  -> 确定性风险规则
  -> 截图观察
  -> 风险结果取 MAX
  -> 任务包状态匹配
  -> Allowed Action 检查
  -> GuidanceDecision
```

安全不变量：

- 规则命中 `high` 或 `critical` 后，普通指导立即终止。
- AI 只能维持或升级规则风险，不能降级。
- 截图缺失、模糊、模型冲突、Schema 无效或任务状态不匹配时返回 `unknown`。
- `unknown` 不得进入 `guide`。
- 模型自由文本不得直接驱动页面跳转、自动操作或外部消息发送。
- 一个指导步骤只能包含一个已审核动作，并给出可观察的成功信号。

## 7. 截图与 Qwen Vision

### 7.1 客户端流程

1. 用户主动选择或拍摄截图。
2. 页面说明处理目的、潜在敏感信息、处理期限和取消方式。
3. 用户在本地预览，并可手动涂抹敏感区域。
4. 用户明确同意后才允许提交。
5. 请求结束后不在 P0 持久化原图。

首版不把自动敏感信息识别宣传为已实现能力。P0 的真实边界是手动遮挡、明确同意、最小传输和请求结束即丢弃。

### 7.2 Vision Provider

```ts
export interface VisionProvider {
  /**
   * 只提取可观察的 UI 事实，不决定是否允许操作。
   * 返回结果必须通过 UIObservationSchema 校验。
   */
  observe(
    input: RedactedScreenshot,
    signal: AbortSignal,
  ): Promise<UIObservation>
}
```

`UIObservation` 至少包含：

- `appId`
- `screenState`
- `elements`
- `confidence`
- `uncertainties`

Provider 规则：

- P0 默认接入百炼 Qwen Vision，但具体模型名、区域端点和价格在实施时根据官方控制台重新核验。
- 模型名和端点只存在于环境配置及基础设施层，不写入领域层。
- 视觉请求硬超时 5 秒，最多一次受控重试。
- 模型输出必须通过 Schema、Risk Policy 和 Allowed Action 三道闸。
- 超时、无法解析、低置信度或输出冲突均返回 `UNKNOWN`。
- 截图中的页面文字属于不可信数据，不得作为系统指令执行。

### 7.3 回放样例

- 建立固定的脱敏截图 fixtures，覆盖三条比赛路径和故障路径。
- fixtures 用于离线回归、状态机验证和没有网络时的演示兜底。
- 回放演示必须明确标注为固定样例，不得描述为实时模型结果。
- 真实 Qwen 调用、固定回放、代码推导图和设计稿分别保存证据标签。

## 8. API 契约

### 8.1 `POST /api/v2/decision`

P0 采用单次 `multipart/form-data` 请求，在一个请求内携带文本、上下文和可选截图，不建立对象存储。

请求字段：

- `text`：用户文字或语音转写。
- `locale`：默认 `zh-CN`。
- `consentId`：提交截图时必填。
- `screenshot`：可选，单张经过本地遮挡的图片。
- `clientContext`：可选的 `appHint`、任务包版本等非权威提示。

响应结构：

```ts
interface DecisionResponse {
  traceId: string
  decision: GuidanceDecision
  policyVersion: string
  modelVersion: string | null
}
```

服务端必须重新计算风险；客户端传入的风险等级、理由和关键词一律不可信。

### 8.2 稳定错误码

- `INVALID_INPUT`
- `CONSENT_REQUIRED`
- `IMAGE_TOO_LARGE`
- `UNSUPPORTED_IMAGE`
- `VISION_TIMEOUT`
- `INVALID_MODEL_OUTPUT`
- `TASK_STATE_NOT_FOUND`
- `RATE_LIMITED`
- `INTERNAL_ERROR`

错误响应不得包含堆栈、密钥、内部路径或模型原始输出。

## 9. 页面与交互

### 9.1 P0 页面

- 首页：文字/语音入口、常见示例和隐私提示。
- 目标确认页：复述用户目标；高风险不得进入此页。
- 截图页：选择、预览、手动遮挡、同意、重拍和取消。
- 一步指导页：当前步骤、目标位置描述、成功信号、播报和错误恢复。
- 风险停止页：解释为什么停止，给出三条以内安全动作。
- 求助卡页：展示脱敏上下文，并提供系统分享或复制。
- `UNKNOWN` 页：说明无法确认，提供重拍、补充描述或找家人三个出口。

### 9.2 适老化约束

- 每屏一个主要动作，最多两个次要动作。
- 主要文字不小于 18 px，关键步骤使用 24–32 px。
- 主按钮高度不低于 64 px。
- 正确使用 `button`、`label`、heading、`status` 和 `alert` 语义。
- 支持键盘、触摸、语音和文字；语音必须有可见替代。
- 在 375 px 竖屏和 200% 文本缩放下不裁切关键操作。
- 不仅依靠颜色表达风险或状态。
- 动效遵循 `prefers-reduced-motion`。

## 10. 家庭交接

### 10.1 求助卡字段

- 用户目标。
- 当前页面或任务状态。
- 已完成步骤。
- 风险等级与面向用户的原因。
- 建议家人核实的事项。
- 创建时间。

求助卡不得包含 OTP、验证码、支付密码、完整银行卡号、身份凭据或未经同意的原始截图。

### 10.2 分享策略

- 分享必须由用户点击触发。
- 优先使用 `navigator.share()` 打开系统分享面板。
- 不支持或调用失败时，降级为复制纯文本。
- 复制失败时允许用户长按选择文字。
- P0 不接入短信供应商、微信发送接口、可信联系人数据库或家属账号。

## 11. 审计、隐私与故障策略

### 11.1 审计事件

每个决策生成 `traceId`，记录：

- 事件类型。
- 策略、任务包和模型版本。
- 输入 hash 与长度。
- 决策结果和 `reasonCode`。
- 延迟与 fallback 状态。

禁止记录：

- 原始文本和原始截图。
- OTP、银行卡号、支付密码和身份证号。
- 完整 prompt/response。
- API Key、Cookie 或其他凭据。

### 11.2 故障分类

- 规则或模板可用、外部模型故障：继续提供确定性风险提醒或进入 `UNKNOWN`。
- 图片无法判断、模型输出冲突或安全状态不确定：进入 `UNKNOWN` 或 `STOP`。
- 高风险规则命中：即使模型不可用，也必须显示风险停止页和求助卡。
- 分享 API 故障：降级复制，不影响风险停止结果。

## 12. 测试与验收

### 12.1 迁移基线

旧项目当前通过底层 `node --test "src/**/*.test.ts"` 复测：208 项测试，207 通过、0 失败、1 跳过。该结果仅证明旧项目本地定向测试，不证明新项目、生产构建、真实 Qwen、线上部署或真实老人可用。

迁移后应逐项核对测试意图，不以测试数量相同作为完成标准。

### 12.2 测试层级

- Domain 单测：风险 MAX、AI 不降级、`UNKNOWN` 不进入 `guide`、高风险不进入普通流程。
- Contract 测试：合法请求、非法 JSON、缺字段、伪造风险字段、超大图片和错误模型输出。
- Vision fixtures：正常页面、模糊截图、错误 App、页面内 Prompt Injection 和低置信度。
- Provider 测试：成功、超时、Abort、非法 Schema、限流和受控重试。
- 组件与无障碍：语义、焦点、对比度、状态消息、键盘和缩放。
- E2E：低风险指导、中风险升级、高风险中止、Qwen 断网和系统分享失败。
- 构建门禁：单测、类型检查、生产构建、E2E、依赖检查全部通过。

### 12.3 关键验收断言

- 所有 `high` 和 `critical` 输入都跳过确认页和教程页。
- `UNKNOWN` 截图不显示具体按钮指导。
- Qwen 超时后不将未知页面当作低风险继续。
- 风险规则与模型结果取最高等级。
- 高风险页面不存在“继续操作”或模拟成功按钮。
- 求助卡和日志不包含敏感凭据。
- 三条比赛案例使用同一生产路由，不使用隐藏分支伪造成功。
- 对外证据能够区分单测、本地浏览器、线上运行、回放样例和真实用户验证。

## 14. 已锁定的默认决策

- 新项目独立建设，旧项目仅作为迁移来源。
- 第一阶段只做比赛闭环 P0。
- 视觉 Provider 采用百炼 Qwen，并保留脱敏回放样例。
- 家庭交接只做用户确认后的系统分享或复制。
- P0 匿名、无数据库、无真实家属账号。
- 简体中文优先，协议保留 `locale`。
- 不把供应商名称、模型名、端点或环境变量读取放入领域层。
- 具体 Qwen 模型、区域、价格和数据政策在接入时依据百炼官方控制台重新核验。

## 15. 需求来源与证据口径

本方案依据以下资料形成：

- 同仓库内 `爸妈别急_小有可为2026参赛PRD_v3.0.docx`
- 同仓库内 `爸妈别急_小有可为2026技术与工程规范_v3.0.docx`
- 旧项目 `021-EasyPhone_AI` 的实际代码、测试和历史运行证据。
- 产品定位与竞品判断的讨论记录。

证据必须严格区分：已实现、单元测试、本地集成、真实模型调用、线上部署、固定回放和真实用户/设备验证。任何模拟结果、代码推导图片或固定样例都不得描述为真实运行成功。
