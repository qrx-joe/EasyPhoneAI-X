# EasyPhoneAI-X 无障碍手机教练执行方案

> 状态：讨论版执行方案  
> 日期：2026-08-14  
> 适用范围：当前 Web/PWA 无障碍闭环，以及后续 Android AccessibilityService 原型  
> 核心原则：先提示、再高亮、最后才评估极少量“确认后操作”；高风险和未知状态永不自动操作。

## 1. 目标

把“爸妈别急 · 安心下一步”从安全问答页面推进为可验证的无障碍手机教练：

1. 用户可以通过大字、语音和读屏完成提问与确认。
2. 系统一次只给一个可逆步骤，并提供真实、可观察的成功信号。
3. 用户可以选择“我看到了”“没看到”“再念一次”或“找家人”。
4. Android 原型在用户明确开启后，可以观察当前页面并高亮下一步。
5. 只有低风险、白名单、可逆动作才允许进入“用户确认后执行”研究。
6. 转账、支付、验证码、密码、授权、屏幕共享等场景必须停止。

## 2. 非目标

本方案不建设以下能力：

- 无人值守地连续操作手机。
- 自动完成支付、转账、退款提交或账号变更。
- 自动读取或填写验证码、密码、银行卡、人脸或指纹信息。
- 自动授予权限、安装 App、打开远程控制或屏幕共享。
- 远程控制老人手机。
- 绕过 Android 的无障碍授权、隐私提示或系统安全限制。
- 在 iPhone 上实现第三方 App 的通用跨 App 自动控制。

## 3. 当前基线

当前项目已经具备：

- `/assist` 统一文字、语音和截图入口。
- 确定性风险分类、风险 MAX 合并、高风险强中止。
- 白名单教程、脱敏求助卡和 UNKNOWN 不放行策略。
- 截图预览、手动遮挡和明确同意。
- 大字、可见焦点、减少动画、对比度测试、语音输入和 TTS。

当前主要缺口：

- 语音识别结束后直接提交，没有“听对了吗”确认。
- 教程只返回第一步，没有可靠的步骤推进状态。
- `successSignal` 使用教程标题，不是每一步的真实页面结果。
- 教程已有 `alternative`，结果页尚未提供“没看到/换种说法”。
- 语速控制组件尚未接入指导流程。
- 结果切换缺少系统性的焦点管理和状态播报。
- 截图 canvas 遮挡没有键盘和读屏等价操作。
- 没有 TalkBack、真实 Android 设备和目标老人用户的验收证据。

## 4. 产品安全策略

### 4.1 风险与行为矩阵

| 风险状态 | 观察页面 | 朗读/高亮 | 给出步骤 | 确认后点击 | 求助 |
|---|---:|---:|---:|---:|---:|
| `low` | 允许 | 允许 | 白名单步骤 | 仅后期白名单原型 | 可选 |
| `medium` | 允许 | 允许 | 仅人工审核步骤 | 禁止 | 推荐 |
| `high` | 最小化观察 | 只播报停止原因 | 禁止 | 禁止 | 必须提供 |
| `critical` | 立即停止进一步读取 | 只播报停止原因 | 禁止 | 禁止 | 必须提供 |
| `unknown` | 允许重新观察 | 只提示无法确认 | 禁止 | 禁止 | 提供 |

### 4.2 永久禁止自动执行的动作

- 支付、转账、充值、提现和退款最终提交。
- 输入、复制、朗读或发送验证码与密码。
- 人脸识别、指纹确认和其他生物认证。
- 安装 App、授予权限、修改安全设置。
- 开启屏幕共享、远程控制、设备管理权限。
- 删除数据、注销账号、恢复出厂设置。
- 发送消息、发布内容或对外分享，除非用户在系统分享面板再次确认。

### 4.3 可进入后期研究的动作

必须同时满足“低风险、白名单、可逆、目标唯一、用户刚刚确认”：

- 点击普通导航项，例如“设置”“显示”“返回”。
- 滚动列表。
- 返回上一页或回到桌面。
- 切换经过审核的非安全类设置；每次切换前单独确认。

## 5. 分阶段执行

### 阶段 A：完成 Web/PWA 无障碍教练闭环

#### 目标

在不申请系统级权限的前提下，先证明老人可以听懂、确认并完成一步指导。

#### 实现项

1. 语音确认
   - 语音结束后只填入文本框，不立即请求决策。
   - 显示并朗读“我听到的是……”。
   - 提供“对，就是这个”“改一改”“重新说”三个出口。

2. 教程步骤状态
   - 为会话保存 `tutorialId`、`stepId`、当前步骤和完成状态。
   - “我看到了”才能推进到下一步。
   - 每次推进重新执行风险检查，不信任客户端步骤索引。
   - 刷新或参数缺失时安全地回到重新描述，不猜测进度。

3. 每步成功信号
   - 将 `successSignal` 放到 `TutorialStep`，由人工逐步审核。
   - 成功信号必须是用户能看到或听到的页面变化。
   - 禁止使用“问题解决了”等不可验证结果替代页面状态。

4. 教练反馈按钮
   - “我看到了”。
   - “没看到”：显示该步骤的 `alternative`。
   - “再念一次”。
   - “说慢一点”：接入现有语速档位。
   - “停止并找家人”。

5. Web 无障碍
   - 请求期间使用 `aria-busy` 或等价状态播报。
   - 新结果出现时将焦点移到结果标题。
   - 指导、停止、错误和 UNKNOWN 使用合适的 live region。
   - 200% 文字缩放下关键按钮不裁切。
   - canvas 遮挡无法操作时提供“不上传截图，改用文字或语音”的等价出口。

#### 验收标准

- 语音结果未经用户确认不会提交。
- 微信声音教程至少可以从第一步推进到最后一步。
- 每一步都有独立、可观察的成功信号。
- “没看到”会换一种说法，不会自动进入下一步。
- 高风险词在任意步骤出现都会立即转为 `stop`。
- 键盘可以完成文字提问、确认、指导、求助和返回。
- TalkBack 能按正确顺序读出标题、动作、成功信号和按钮。

#### 验证

```powershell
pnpm.cmd test
pnpm.cmd typecheck
pnpm.cmd build
pnpm.cmd test:e2e
```

另需人工记录：

- Android Chrome + TalkBack。
- 375 px 竖屏。
- 200% 文字缩放。
- Web Speech 不支持、拒绝权限、识别失败。
- TTS 不支持、播放失败和用户主动停止。

#### 停止条件

如果步骤状态会让高风险输入绕过正式决策链，立即停止该阶段并先修复服务端状态校验。

### 阶段 B：Android 只读观察原型

#### 进入条件

- 阶段 A 全部验收通过。
- 完成 Android 原型边界 ADR。
- 明确首批测试设备、Android 版本和目标 App 版本。
- 用户明确同意安装原型并手动开启无障碍服务。

#### 技术选择

- Kotlin 原生 Android 应用。
- `AccessibilityService` 只用于辅助目标用户。
- 第一版只读取可见无障碍节点，不调用点击和手势动作。
- 当前 Next.js 项目继续承载安全策略与教程；Android 端通过受控契约提交结构化观察。
- Android 工程放入当前仓库还是独立仓库，必须先写 ADR 决定，不在本方案中预设。

#### 最小观察契约

只发送决策所需字段，不上传完整节点树：

```ts
interface AccessibilityObservation {
  packageName: string
  screenSignature: string
  visibleElements: Array<{
    role: string
    label: string
    clickable: boolean
    enabled: boolean
    bounds: { left: number; top: number; right: number; bottom: number }
  }>
  observedAt: string
  consentId: string
}
```

数据处理要求：

- 在 Android 本地先过滤密码框、验证码、长数字和个人信息。
- 默认不上传截图、不记录完整页面文本。
- 日志只记录脱敏 trace、策略版本、决策类型和失败原因。
- App 切换、息屏、锁屏或服务暂停后立即清除内存观察结果。

#### 验收标准

- 服务只能由用户在系统设置中手动开启。
- 页面上持续显示服务状态，并提供一键暂停入口。
- 能识别当前 App、页面文字和可点击元素。
- 密码输入框、验证码和支付页面不会进入普通指导。
- 未识别 App、节点缺失或页面冲突返回 `unknown`。
- 原型不包含任何自动点击代码路径。

#### 停止条件

出现敏感信息泄露、服务后台持续读取、无法可靠暂停，或页面状态误判可能引导支付时，停止原型测试。

### 阶段 C：高亮与语音提示

#### 目标

系统看懂当前页面后，只指出下一步位置，仍由用户亲自点击。

#### 实现项

- 将教程步骤绑定到允许的 App、页面签名和目标控件特征。
- 只有唯一目标且风险为 `low` 时显示高亮。
- 高亮同时给出控件名称和语音说明，不能只靠颜色。
- 页面变化后重新观察，旧高亮立即失效。
- 找不到唯一目标时显示“我还不能确定”，不使用坐标猜测。

#### 验收标准

- 高亮目标与 TalkBack 当前可读名称一致。
- 页面滚动、弹窗或 App 切换后不会继续指向旧位置。
- 同名按钮存在多个时不高亮，并进入澄清。
- 高风险、未知和非白名单页面没有高亮。

#### 停止条件

如果只能依赖固定屏幕坐标，或者目标节点不能稳定区分，不进入下一阶段。

### 阶段 D：极少量“确认后操作”实验

#### 进入条件

- 阶段 C 在真实设备和目标用户测试中稳定通过。
- 每个候选动作有人工审核任务包和回归样例。
- 本地动作前保险丝与服务端风险判断均已实现。
- 完成隐私、应用商店政策和法律合规核验。

#### 执行流程

```text
用户主动请求帮助
  → 读取当前页面
  → 本地敏感词保险丝
  → 服务端风险与任务状态判断
  → 生成一个白名单动作提案
  → 朗读动作、目标和预期结果
  → 用户明确点击“确认操作”
  → 再次核对页面签名和目标唯一性
  → 执行一个动作
  → 立即停止并重新观察
```

#### 动作约束

- 一次确认只执行一个动作，不能连续点击。
- 动作提案短时有效；页面变化后立即过期。
- 执行前后都必须检查页面签名。
- 首批只研究点击普通导航项和滚动。
- 不研究文字输入、支付、授权、发送、删除和账号变更。

#### 验收标准

- 用户未确认时动作执行次数为 0。
- 页面或目标发生变化时动作执行次数为 0。
- `medium/high/critical/unknown` 自动动作次数为 0。
- 每个动作都有本地、脱敏、可审计的结果记录。
- 用户可以在动作前、动作中和动作后立即暂停服务。

#### 停止条件

任何一次越权点击、错误目标点击或高风险页面动作都视为阶段失败，回退到只提示模式。

## 6. 任务包改造

每个教程需要从“文本列表”升级为版本化任务包：

```ts
interface ReviewedTaskStep {
  id: string
  appPackage: string
  supportedVersions: string[]
  screenSignature: string
  instruction: string
  alternative: string
  successSignal: string
  target: {
    role: string
    labels: string[]
  }
  allowedAction: 'none' | 'highlight' | 'click' | 'scroll'
  maxRisk: 'low' | 'medium'
  stopKeywords: string[]
}
```

要求：

- App 或系统版本变化后重新审核。
- 找不到匹配版本时降级为文字提示或 `unknown`。
- 任务包不能包含支付确认、账号安全和权限授予动作。
- 教程内容、目标匹配和允许动作必须使用同一版本号进入审计记录。

## 7. 测试与证据

### 自动化测试

- 风险策略与动作许可矩阵单元测试。
- 每步成功信号和任务包 Schema 测试。
- 页面签名变化、重复目标和节点缺失测试。
- 高风险词出现时动作提案强制清空测试。
- AccessibilityService 使用固定节点树 fixture 的离线回归。
- Web 主流程与 Android 端到端测试分开记录。

### 真实设备测试

至少覆盖：

- 两个不同品牌的 Android 设备；具体型号由目标用户设备调查决定。
- TalkBack 开启与关闭。
- 大字体、显示放大和减少动画。
- 网络正常、超时、断网和服务端异常。
- App 更新导致页面结构变化。
- 锁屏、来电、系统弹窗和 App 快速切换。

### 目标用户测试

首轮邀请 3–5 位目标用户完成固定任务，记录：

- 不依赖家人完成率。
- 每步重复次数和“没看到”比例。
- 语音识别提交前修改率。
- 误触、迷路和主动退出位置。
- 高风险场景继续操作率，目标必须为 0。
- 求助卡是否足以让家人理解并接手。

### 证据等级

所有材料必须标记为以下一种：

- `[代码检查]`
- `[自动化测试]`
- `[固定节点回放]`
- `[本地模拟器]`
- `[真实 Android 设备]`
- `[目标用户测试]`

不得用固定回放或模拟器结果代替真实设备与目标用户证据。

## 8. 工作包顺序

| 顺序 | 工作包 | 主要交付物 | 进入下一项的门禁 |
|---|---|---|---|
| 1 | 语音确认 | 听写确认界面与回归测试 | 未确认不提交 |
| 2 | 步骤状态机 | 服务端校验的步骤推进 | 不可跳步或绕过风险判断 |
| 3 | 成功信号与反馈 | “看到了/没看到/再念一次” | 三条教程可完整走通 |
| 4 | Web 无障碍验收 | TalkBack、键盘、200% 缩放记录 | 无阻断问题 |
| 5 | Android ADR | 工程边界、数据契约、权限说明 | 评审通过 |
| 6 | 只读观察原型 | AccessibilityService 观察层 | 无点击路径、无敏感数据泄露 |
| 7 | 高亮提示 | 页面目标匹配与语音提示 | 唯一目标匹配稳定 |
| 8 | 确认后操作实验 | 极小白名单动作 | 安全门禁和真实设备验收通过 |

## 9. 下一次开工点

先执行阶段 A 的第一个独立改动：

> 将语音识别从“结束后直接提交”改为“结束后显示识别结果，由用户确认后提交”。

完成标准：

- 语音只更新输入内容。
- 用户可以确认、编辑或重新录音。
- 未确认的语音不会调用决策 API。
- 高风险输入仍通过正式 `/api/v2/decision` 决策链。
- 单元测试、类型检查、构建和相关 E2E 通过。
